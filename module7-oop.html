1. Introduction to Strings in C++

Definition: A string is a sequence of characters used to store text. In C++, strings can be represented in two ways: using C-style character arrays (char[]) or using the std::string class from the Standard Library.

Real-Life Example

A user's name, a product description, and a chat message are all strings. They can be stored, compared, searched, and modified in a program.

2. Character Arrays and the string Class

Character Arrays (C-strings)

Definition: A character array is a fixed-size sequence of characters terminated by the null character '\0'. It is the traditional way of representing text in C and C++.

Syntax

char name[20] = "Hello";
char greeting[] = "World";

Characteristics

  • Fixed size, decided at declaration.
  • Must end with a null character.
  • Requires C-string functions from <cstring> for manipulation.

Real-Life Example

A fixed-capacity label on a jar (for example, 20 characters) that holds a short product name.

Code Example

#include <iostream>
using namespace std;

int main() {
    char name[20] = "Ali";
    cout << "Name: " << name << endl;
    cout << "First letter: " << name[0] << endl;
    return 0;
}
Output: Name: Ali First letter: A

The std::string Class

Definition: The std::string class is a dynamic, object-oriented string type provided by the C++ Standard Library. It handles memory automatically and offers many member functions for manipulation.

Syntax

#include <string>
string name = "Hello";
string greeting("World");

Characteristics

  • Dynamic size; grows and shrinks automatically.
  • No need to worry about the null terminator.
  • Supports operators such as +, ==, <, and [] out of the box.
  • Provides member functions such as length(), substr(), find(), append().

Real-Life Example

A text field in a chat application that accepts any length of message without the user worrying about buffer sizes.

Code Example

#include <iostream>
#include <string>
using namespace std;

int main() {
    string first = "Hello";
    string second = "World";
    string combined = first + " " + second;

    cout << combined << endl;
    cout << "Length: " << combined.length() << endl;

    return 0;
}
Output: Hello World Length: 11

4. Introduction to Exception Handling

Definition: Exception handling is a mechanism that allows a program to detect and respond to unusual or erroneous situations at runtime without crashing. In C++, it is implemented using the keywords try, catch, and throw.

Purpose

  • Separates error-handling code from normal logic.
  • Allows errors to propagate up the call stack.
  • Ensures resources are released properly.
  • Prevents abrupt program termination.

Real-Life Example

When withdrawing money from an ATM, if the requested amount exceeds the balance, the machine displays an appropriate message and returns the card. It does not crash or dispense incorrect amounts.

Exception Handling Flow Diagram

+------------------+ | try | | risky code | +--------+---------+ | exception thrown? / \ yes no | | v v +------+ continue |catch | execution |handle| +------+

6. try, catch, and throw

try: A block of code that may raise an exception.

catch: A block that handles a specific type of exception.

throw: A statement that raises an exception when an error is detected.

Syntax

try {
    // code that might throw
    if (problem) throw exceptionValue;
}
catch (ExceptionType name) {
    // handle
}
catch (...) {
    // catch-all
}

Rules

  • A try block must be followed by at least one catch block.
  • The thrown value's type determines which catch block runs.
  • If no catch matches, the program terminates.
  • catch (...) catches any type of exception.

Real-Life Example

A form submits user data. The try block validates and submits. If the network fails, an exception is thrown, and the catch block displays a friendly error and keeps the data intact.

Code Example

#include <iostream>
using namespace std;

int main() {
    try {
        int a = 10;
        int b = 0;
        if (b == 0) throw "Division by zero";
        cout << a / b << endl;
    }
    catch (const char* msg) {
        cout << "Caught: " << msg << endl;
    }
    return 0;
}
Output: Caught: Division by zero

7. Multiple Catch Blocks

Definition: Multiple catch blocks allow a single try block to handle different types of exceptions separately. The first matching catch block is executed.

Real-Life Example

An order processing system handles various failures: missing product (logic error), out-of-stock (runtime error), and unknown error (catch-all). Each is handled with a different message.

Code Example

#include <iostream>
using namespace std;

int main() {
    try {
        int choice = 2;
        if (choice == 1) throw 404;
        else if (choice == 2) throw string("Out of stock");
        else throw 3.14;
    }
    catch (int code) {
        cout << "Error code: " << code << endl;
    }
    catch (string msg) {
        cout << "Message: " << msg << endl;
    }
    catch (...) {
        cout << "Unknown exception" << endl;
    }
    return 0;
}
Output: Message: Out of stock

8. Nested Exception Handling

Definition: Nested exception handling means placing a try-catch block inside another try or catch block. This allows an inner operation to handle its own errors or to rethrow them to the outer block.

Real-Life Example

A banking system processes a loan application. The inner step validates the credit score, the outer step handles the final approval. If the credit score fails, the inner exception is handled or rethrown, and the outer block decides whether to proceed with an alternative.

Code Example

#include <iostream>
using namespace std;

int main() {
    try {
        try {
            throw runtime_error("Inner failure");
        }
        catch (runtime_error &e) {
            cout << "Inner caught: " << e.what() << endl;
            throw;                       // rethrow to outer
        }
    }
    catch (runtime_error &e) {
        cout << "Outer caught: " << e.what() << endl;
    }
    return 0;
}
Output: Inner caught: Inner failure Outer caught: Inner failure

9. User-Defined Exceptions

Definition: A user-defined exception is a custom class that inherits from std::exception (or another standard exception). It allows a program to define and throw domain-specific errors with meaningful names and messages.

Syntax

#include <exception>

class MyException : public exception {
public:
    const char* what() const noexcept override {
        return "My custom error";
    }
};

Real-Life Example

A banking application defines InsufficientFundsException so that the exception is clearly named and self-documenting when reading the code.

Code Example

#include <iostream>
#include <exception>
using namespace std;

class InsufficientFundsException : public exception {
private:
    double shortfall;
public:
    InsufficientFundsException(double s) : shortfall(s) { }

    const char* what() const noexcept override {
        return "Insufficient funds";
    }
    double getShortfall() const { return shortfall; }
};

class BankAccount {
private:
    double balance;
public:
    BankAccount(double b) : balance(b) { }

    void withdraw(double amount) {
        if (amount > balance)
            throw InsufficientFundsException(amount - balance);
        balance -= amount;
    }
};

int main() {
    BankAccount acc(500);
    try {
        acc.withdraw(800);
    }
    catch (InsufficientFundsException &e) {
        cout << e.what() << ": short by $" << e.getShortfall() << endl;
    }
    return 0;
}
Output: Insufficient funds: short by $300

10. Stack Unwinding

Definition: Stack unwinding is the process that occurs when an exception is thrown and the program exits multiple function calls to reach a matching catch block. As each stack frame is destroyed, the destructors of local objects in those frames are called automatically.

Key Points

  • Local objects are destroyed in reverse order of creation.
  • Ensures resources are released properly even when an error occurs.
  • RAII (Resource Acquisition Is Initialization) is built on this guarantee.

Real-Life Example

If an emergency evacuation occurs during a meeting, every department leaves the building in reverse order, ensuring all rooms are cleared and lights are turned off.

Stack Unwinding Diagram

Call stack before throw: +-------------------+ | main() | +-------------------+ | funcA() | +-------------------+ | funcB() | <-- exception thrown here +-------------------+ Unwinding: funcB destroyed funcA destroyed main catches exception

Code Example

#include <iostream>
using namespace std;

class Resource {
public:
    Resource() { cout << "Resource acquired" << endl; }
    ~Resource() { cout << "Resource released" << endl; }
};

void inner() {
    Resource r;
    throw runtime_error("Error in inner");
}

void outer() {
    Resource r;
    inner();
}

int main() {
    try {
        outer();
    }
    catch (runtime_error &e) {
        cout << "Caught: " << e.what() << endl;
    }
    return 0;
}
Output: Resource acquired Resource acquired Resource released Resource released Caught: Error in inner

11. Dynamic Memory Management

Definition: Dynamic memory management is the process of allocating and freeing memory at runtime. In C++, this is done with the new and delete operators (and the array forms new[] and delete[]).

Real-Life Example

A reservation system allocates seats (memory) as customers book them and releases them when they cancel. Seats are assigned dynamically, not pre-built for every possible customer.

Code Example

#include <iostream>
using namespace std;

int main() {
    int *p = new int(100);
    cout << "Value: " << *p << endl;
    delete p;

    int *arr = new int[5];
    for (int i = 0; i < 5; i++) arr[i] = i + 1;
    for (int i = 0; i < 5; i++) cout << arr[i] << " ";
    cout << endl;
    delete[] arr;

    return 0;
}
Output: Value: 100 1 2 3 4 5

12. Memory Leaks and Dangling Pointers

Memory Leak

Definition: A memory leak occurs when dynamically allocated memory is never released, so the program gradually loses available memory.

Causes

  • Calling new without a matching delete.
  • Losing the only pointer to allocated memory.
  • Exceptions skipping past the cleanup code.

Real-Life Example

A hotel rents out a room but forgets to record the checkout. The room remains marked as occupied forever, reducing capacity over time.

Code Example (Leak)

void leakExample() {
    int *p = new int[100];      // allocated
    // forgot delete[] p;       // leak
}

Dangling Pointer

Definition: A dangling pointer is a pointer that still references memory that has already been freed. Using it leads to undefined behavior.

Causes

  • Deleting memory but keeping the pointer.
  • Returning a pointer to a local variable that no longer exists.

Real-Life Example

A phone number still stored in a contact after the person has changed their number. The contact points to a phone that no longer answers.

Code Example (Dangling Pointer)

void danglingExample() {
    int *p = new int(10);
    delete p;
    // *p = 20;                  // ERROR: p is now dangling
    p = nullptr;                 // safe practice
}

Prevention

IssuePrevention
Memory leakMatch every new with delete (or delete[] with new[])
Dangling pointerSet pointer to nullptr after delete; avoid returning addresses of locals
Double deleteDelete only once; use smart pointers in modern C++

Practical 5: Handling Multiple Exceptions

#include <iostream>
#include <stdexcept>
using namespace std;

void process(int code) {
    if (code == 1) throw invalid_argument("Invalid input");
    if (code == 2) throw out_of_range("Value too large");
    if (code == 3) throw runtime_error("Generic failure");
}

int main() {
    for (int c = 1; c <= 4; c++) {
        try {
            process(c);
            cout << "Code " << c << ": OK" << endl;
        }
        catch (invalid_argument &e) {
            cout << "Code " << c << ": " << e.what() << endl;
        }
        catch (out_of_range &e) {
            cout << "Code " << c << ": " << e.what() << endl;
        }
        catch (exception &e) {
            cout << "Code " << c << ": " << e.what() << endl;
        }
    }
    return 0;
}
Output: Code 1: Invalid input Code 2: Value too large Code 3: Generic failure Code 4: OK

Practical 9: Identifying Memory Leaks

#include <iostream>
using namespace std;

void createsLeak() {
    int *data = new int[1000];
    data[0] = 1;
    // missing delete[] data;  <-- memory leak
}

void noLeak() {
    int *data = new int[1000];
    data[0] = 1;
    delete[] data;             // proper cleanup
}

int main() {
    for (int i = 0; i < 100; i++) createsLeak();
    for (int i = 0; i < 100; i++) noLeak();
    cout << "Done. Monitor memory to observe leaks." << endl;
    return 0;
}
Output: Done. Monitor memory to observe leaks.
Tip: Tools such as Valgrind (Linux) and Visual Studio's memory profiler help detect leaks automatically during testing.

Practical 10: Understanding Dangling Pointers

#include <iostream>
using namespace std;

int main() {
    int *p = new int(50);
    cout << "Value: " << *p << endl;

    delete p;                      // memory freed
    p = nullptr;                   // safe

    return 0;
}
Output: Value: 50 Pointer set to nullptr, safe to use.
