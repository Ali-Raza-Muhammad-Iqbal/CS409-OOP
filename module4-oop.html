Part A: Theory Topics

1. Introduction to Inheritance and Its Advantages

Definition: Inheritance is a mechanism in object-oriented programming by which one class (the derived class) acquires the properties and behaviors of another class (the base class). It promotes code reusability and establishes an "is-a" relationship between classes.

Key Terms

  • Base class (parent): The class whose members are inherited.
  • Derived class (child): The class that inherits members from the base class.
  • Reusability: Existing code can be reused without rewriting it.

Advantages of Inheritance

No.AdvantageExplanation
1Code reusabilityCommon code is written once and reused by derived classes.
2ExtensibilityNew features can be added without modifying existing code.
3Reduced redundancyDuplicate code is avoided across related classes.
4MaintainabilityChanges in the base class propagate to derived classes.
5Polymorphism supportEnables dynamic binding and virtual functions.
6Real-world modelingNatural "is-a" hierarchies are easy to represent.

Real-Life Example

A Car is a Vehicle, a Dog is an Animal, a Savings Account is a Bank Account. Each derived concept inherits the general features of its parent while adding its own specifics.

2. Base Class and Derived Class

Base Class: The original class whose members are inherited.

Derived Class: The class that inherits members from the base class and may add new members of its own.

Syntax

class BaseClass {
    // members
};

class DerivedClass : accessMode BaseClass {
    // additional members
};

Inheritance Relationship Diagram

+----------------+ | Base Class | | (Vehicle) | +--------+-------+ | | inherits v +----------------+ | Derived Class | | (Car) | +----------------+

Code Example

#include <iostream>
using namespace std;

class Vehicle {
public:
    void start() { cout << "Vehicle starting" << endl; }
};

class Car : public Vehicle {
public:
    void drive() { cout << "Car driving" << endl; }
};

int main() {
    Car c;
    c.start();       // inherited
    c.drive();       // own method
    return 0;
}
Output: Vehicle starting Car driving

3. Types of Inheritance

C++ supports five types of inheritance: single, multilevel, multiple, hierarchical, and hybrid.

3.1 Single Inheritance

Definition: One derived class inherits from exactly one base class.
+--------+ +--------+ | Base A | ------>| Der. B | +--------+ +--------+
class Animal {
public:
    void eat() { cout << "Eating" << endl; }
};

class Dog : public Animal {
public:
    void bark() { cout << "Barking" << endl; }
};

3.2 Multilevel Inheritance

Definition: A derived class becomes the base class for another derived class, forming a chain.
+--------+ +--------+ +--------+ | Base A |--->| Der. B |--->| Der. C | +--------+ +--------+ +--------+
class Animal {
public:
    void eat() { cout << "Eating" << endl; }
};

class Dog : public Animal {
public:
    void bark() { cout << "Barking" << endl; }
};

class Puppy : public Dog {
public:
    void weep() { cout << "Weeping" << endl; }
};

3.3 Multiple Inheritance

Definition: A single derived class inherits from two or more base classes.
+--------+ +--------+ | Base A | | Base B | +---+----+ +----+---+ \ / \ / v v +--------+ | Der. C | +--------+
class Printer {
public:
    void print() { cout << "Printing" << endl; }
};

class Scanner {
public:
    void scan() { cout << "Scanning" << endl; }
};

class Copier : public Printer, public Scanner {
public:
    void copy() {
        print();
        scan();
    }
};

3.4 Hierarchical Inheritance

Definition: Two or more derived classes inherit from a single base class.
+--------+ | Base A | +---+----+ / | \ v v v +------+ +-----+ +------+ | Der.B| |Der.C| |Der.D | +------+ +-----+ +------+
class Shape {
public:
    void draw() { cout << "Drawing shape" << endl; }
};

class Circle : public Shape { };
class Square : public Shape { };
class Triangle : public Shape { };

3.5 Hybrid Inheritance

Definition: A combination of two or more of the above inheritance types, such as multiple plus hierarchical or multilevel plus hierarchical.
+--------+ | Base A | +---+----+ / \ v v +--------+ +--------+ | B | | C | +---+----+ +----+---+ \ / \ / v v +--------+ | D | +--------+
class A {
public:
    void showA() { cout << "A" << endl; }
};

class B : public A { };
class C : public A { };

class D : public B, public C { };
Note: Without virtual inheritance in the example above, class D receives two copies of A's members, causing ambiguity.

4. Public, Private, and Protected Inheritance

Definition: The inheritance access specifier determines how the access level of inherited members is transformed in the derived class.

Access Transformation Table

Base Memberpublic inheritanceprotected inheritanceprivate inheritance
publicpublicprotectedprivate
protectedprotectedprotectedprivate
privatenot accessiblenot accessiblenot accessible

Real-Life Analogy

  • public inheritance – "is-a" relationship (a Car is a Vehicle).
  • protected inheritance – "is-implemented-in-terms-of" within a family (only derived classes may use the base).
  • private inheritance – strict internal reuse; externally the derived class does not reveal the base.

Syntax

class Derived : public    Base { };
class Derived : protected Base { };
class Derived : private   Base { };

5. Function Overriding

Definition: Function overriding occurs when a derived class defines a function with the same name, return type, and parameter list as a function in its base class. The derived version replaces the base version when called through a derived object.

Function Overloading vs Overriding

FeatureOverloadingOverriding
ScopeSame classBase and derived class
ParametersMust differMust be identical
BindingCompile-timeRuntime (if virtual)
KeywordNot requiredvirtual, override recommended

Syntax

class Base {
public:
    virtual void show() { /* base version */ }
};

class Derived : public Base {
public:
    void show() override { /* derived version */ }
};

Real-Life Example

All animals "speak," but a Dog barks and a Cat meows. The base behavior is replaced by each derived version.

Code Example

#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() { cout << "Some sound" << endl; }
};

class Dog : public Animal {
public:
    void sound() override { cout << "Bark" << endl; }
};

class Cat : public Animal {
public:
    void sound() override { cout << "Meow" << endl; }
};

int main() {
    Dog d; Cat c;
    d.sound();
    c.sound();
    return 0;
}
Output: Bark Meow

6. Constructor and Destructor Execution in Inheritance

Definition: When an object of a derived class is created, constructors execute from base to derived. When it is destroyed, destructors execute from derived to base.

Execution Order

Construction: Base --> Intermediate --> Derived Destruction: Derived --> Intermediate --> Base

Rules

  • Base class constructors are called first, in the order of inheritance.
  • Then the derived class constructor body executes.
  • Destructors are called in the exact reverse order.
  • If the base class has no default constructor, the derived constructor must explicitly call it using an initializer list.

Code Example

#include <iostream>
using namespace std;

class Base {
public:
    Base() { cout << "Base constructor" << endl; }
    ~Base() { cout << "Base destructor" << endl; }
};

class Derived : public Base {
public:
    Derived() { cout << "Derived constructor" << endl; }
    ~Derived() { cout << "Derived destructor" << endl; }
};

int main() {
    Derived d;
    return 0;
}
Output: Base constructor Derived constructor Derived destructor Base destructor

7. Ambiguity in Multiple Inheritance

Definition: Ambiguity arises in multiple inheritance when two or more base classes contain a member (function or data) with the same name. The compiler cannot decide which version to use when the derived class calls that member.

Diamond Problem Diagram

+--------+ | Base | +---+----+ / \ v v +--------+ +--------+ | B | | C | +---+----+ +----+---+ \ / \ / v v +--------+ | D | +--------+ D inherits two copies of Base, causing ambiguity.

Code Example (Ambiguity)

class A {
public:
    void show() { cout << "A" << endl; }
};

class B : public A { };
class C : public A { };

class D : public B, public C { };

int main() {
    D d;
    // d.show();       // AMBIGUOUS
    d.B::show();       // resolved using scope resolution
    d.C::show();
    return 0;
}

Ways to Resolve Ambiguity

MethodDescription
Scope resolutionUse obj.Base::member() to specify which version to call
Override in derived classRedefine the member in the derived class to hide both base versions
Virtual base classEnsure only one copy of the common base exists

8. Virtual Base Classes

Definition: A virtual base class is used in hybrid or multiple inheritance to prevent multiple copies of a common base class. When a base class is inherited virtually, only one shared instance of that base exists in the derived class.

Purpose

  • Solves the diamond problem.
  • Ensures a single copy of the common base class.
  • Reduces memory waste and removes ambiguity.

Syntax

class B : virtual public A { };
class C : virtual public A { };
class D : public B, public C { };

Diamond Problem Resolution Diagram

+--------+ | Base | (virtual) +---+----+ / \ v v +--------+ +--------+ | B(v) | | C(v) | +---+----+ +----+---+ \ / \ / v v +--------+ | D | only one copy of Base +--------+

Code Example

#include <iostream>
using namespace std;

class A {
public:
    int value = 10;
};

class B : virtual public A { };
class C : virtual public A { };

class D : public B, public C { };

int main() {
    D d;
    cout << d.value << endl;    // no ambiguity now
    return 0;
}
Output: 10

9. Code Reusability Through Inheritance

Definition: Code reusability through inheritance means writing common functionality once in a base class and reusing it in all derived classes, instead of duplicating it.

Benefits

  • Single point of maintenance for shared logic.
  • Reduced total source code size.
  • Improved consistency across related classes.
  • Faster development through reuse of tested code.

Real-Life Example

A payroll system defines an Employee base class with name, id, and calculateSalary(). The derived classes Manager, Engineer, and Intern reuse these members and add their own logic without rewriting the common parts.

Code Example

#include <iostream>
using namespace std;

class Employee {
protected:
    string name;
    int id;
public:
    Employee(string n, int i) : name(n), id(i) { }

    void showInfo() {
        cout << name << " (ID: " << id << ")" << endl;
    }
};

class Manager : public Employee {
public:
    Manager(string n, int i) : Employee(n, i) { }

    void role() { cout << "Manages the team" << endl; }
};

class Engineer : public Employee {
public:
    Engineer(string n, int i) : Employee(n, i) { }

    void role() { cout << "Develops software" << endl; }
};

int main() {
    Manager m("Ali", 101);
    Engineer e("Sara", 102);

    m.showInfo(); m.role();
    e.showInfo(); e.role();
    return 0;
}
Output: Ali (ID: 101) Manages the team Sara (ID: 102) Develops software

Practical 4: Applying Different Inheritance Access Modes

#include <iostream>
using namespace std;

class Base {
public:
    int a = 1;
protected:
    int b = 2;
private:
    int c = 3;
};

class PublicDerived : public Base {
public:
    void show() {
        cout << "a=" << a << " b=" << b << endl;   // c not accessible
    }
};

class ProtectedDerived : protected Base {
public:
    void show() {
        cout << "a=" << a << " b=" << b << endl;
    }
};

class PrivateDerived : private Base {
public:
    void show() {
        cout << "a=" << a << " b=" << b << endl;
    }
};

int main() {
    PublicDerived p;
    p.show();

    ProtectedDerived pr;
    pr.show();

    PrivateDerived pv;
    pv.show();

    // cout << p.a;    // allowed in public only
    // cout << pr.a;   // NOT allowed; now protected
    // cout << pv.a;   // NOT allowed; now private
    return 0;
}
Output: a=1 b=2 a=1 b=2 a=1 b=2

Practical 5: Implementing Function Overriding

#include <iostream>
using namespace std;

class Shape {
public:
    virtual void area() {
        cout << "Area of shape not defined" << endl;
    }
};

class Rectangle : public Shape {
private:
    int l, w;
public:
    Rectangle(int length, int width) { l = length; w = width; }
    void area() override {
        cout << "Rectangle area: " << l * w << endl;
    }
};

class Triangle : public Shape {
private:
    int base, height;
public:
    Triangle(int b, int h) { base = b; height = h; }
    void area() override {
        cout << "Triangle area: " << 0.5 * base * height << endl;
    }
};

int main() {
    Rectangle r(4, 5);
    Triangle t(6, 3);

    Shape *s1 = &r;
    Shape *s2 = &t;
    s1->area();
    s2->area();

    return 0;
}
Output: Rectangle area: 20 Triangle area: 9

Practical 7: Resolving Ambiguity in Multiple Inheritance

#include <iostream>
using namespace std;

class A {
public:
    void show() { cout << "A::show" << endl; }
};

class B : public A { };
class C : public A { };
class D : public B, public C { };

int main() {
    D d;

    // d.show();        // ambiguous
    d.B::show();        // resolve via scope
    d.C::show();        // resolve via scope

    return 0;
}
Output: A::show A::show

Alternative Resolution: Overriding in D

class D : public B, public C {
public:
    void show() { cout << "D::show" << endl; }   // hides both base versions
};

Practical 8: Implementing Virtual Base Classes

#include <iostream>
using namespace std;

class Person {
protected:
    string name;
public:
    Person(string n) : name(n) { }
    void show() { cout << "Name: " << name << endl; }
};

class Student : virtual public Person {
public:
    Student(string n) : Person(n) { }
};

class Employee : virtual public Person {
public:
    Employee(string n) : Person(n) { }
};

class Intern : public Student, public Employee {
public:
    Intern(string n) : Person(n), Student(n), Employee(n) { }
};

int main() {
    Intern i("Ali");
    i.show();            // single shared Person instance
    return 0;
}
Output: Name: Ali
Note: When a virtual base class is used, the most-derived class (Intern) is responsible for calling the virtual base class constructor directly. This ensures only one instance of the shared base exists.
