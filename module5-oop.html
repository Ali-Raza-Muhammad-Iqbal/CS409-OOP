Part A: Theory Topics

1. Introduction to Polymorphism and Its Advantages

Definition: Polymorphism is the ability of a single interface, function name, or operator to behave differently depending on the object or data types involved. In C++, polymorphism allows the same function call to execute different code at compile time or at runtime.

Meaning of the Word

The term comes from Greek: poly (many) and morph (forms). Thus, polymorphism means "many forms."

Advantages of Polymorphism

No.AdvantageExplanation
1FlexibilityThe same interface can work with different data types.
2ExtensibilityNew derived types can be added without changing existing code.
3Code reuseCommon interfaces avoid duplication.
4DecouplingClients depend only on the base interface.
5ReadabilityOne familiar name for related operations.
6Dynamic behaviorDecisions can be deferred until runtime.

Real-Life Example

The word "draw" has a single interface, but a Circle, a Square, and a Triangle each draw differently. The person calling draw() does not need to know which shape is drawing.

Types of Polymorphism

Polymorphism | +-----------+-----------+ | | Compile-time Runtime (static binding) (dynamic binding) | | +-----+-----+ | | | | Function Operator Virtual functions overloading overloading and Function overriding

2. Compile-Time Polymorphism

Definition: Compile-time polymorphism, also called static polymorphism or early binding, is resolved by the compiler at compile time. It is achieved through function overloading, operator overloading, and templates.

Features

  • The function call is resolved before the program runs.
  • Faster execution because no runtime lookup is involved.
  • Achieved via overloading or templates.

Real-Life Example

A restaurant offers multiple versions of the "order" action: order a drink, order a meal, or order a meal with dessert. The server knows which action to take based on how the request is phrased at the counter.

Code Example

#include <iostream>
using namespace std;

class Calculator {
public:
    int add(int a, int b) { return a + b; }
    double add(double a, double b) { return a + b; }
    int add(int a, int b, int c) { return a + b + c; }
};

int main() {
    Calculator c;
    cout << c.add(2, 3) << endl;
    cout << c.add(2.5, 3.5) << endl;
    cout << c.add(1, 2, 3) << endl;
    return 0;
}
Output: 5 6 6

3. Runtime Polymorphism

Definition: Runtime polymorphism, also called dynamic polymorphism or late binding, is resolved at the time the program is executed. In C++, it is achieved through virtual functions and inheritance.

Features

  • Function call is resolved during program execution.
  • Uses the virtual function table (vtable) mechanism.
  • Enables true "one interface, many behaviors" design.

Real-Life Example

A universal remote control has a "play" button. When it points at a TV, it plays the TV. When it points at a DVD player, it plays the DVD. The button behaves differently depending on the target, and the target is determined at the time of use.

Code Example

#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() { cout << "Drawing a generic shape" << endl; }
};

class Circle : public Shape {
public:
    void draw() override { cout << "Drawing a circle" << endl; }
};

class Square : public Shape {
public:
    void draw() override { cout << "Drawing a square" << endl; }
};

int main() {
    Shape *s1 = new Circle();
    Shape *s2 = new Square();
    s1->draw();
    s2->draw();
    delete s1;
    delete s2;
    return 0;
}
Output: Drawing a circle Drawing a square

4. Function Overloading (Recap)

Definition: Function overloading is the definition of multiple functions with the same name but different parameter lists in the same scope. It is a form of compile-time polymorphism.

Syntax

returnType functionName(dataType param1);
returnType functionName(dataType param1, dataType param2);
returnType functionName(double param1);

Real-Life Example

A printing service accepts documents, photos, or posters. The action is the same ("print") but the input type differs.

Code Example

#include <iostream>
using namespace std;

class Printer {
public:
    void print(int value) { cout << "Integer: " << value << endl; }
    void print(double value) { cout << "Double: " << value << endl; }
    void print(string value) { cout << "String: " << value << endl; }
};

int main() {
    Printer p;
    p.print(42);
    p.print(3.14);
    p.print("Hello");
    return 0;
}
Output: Integer: 42 Double: 3.14 String: Hello

5. Operator Overloading (Recap)

Definition: Operator overloading allows existing operators to be redefined for user-defined types. It is another form of compile-time polymorphism.

Real-Life Example

The plus sign "+" adds numbers, concatenates strings, and merges containers depending on the types involved.

Code Example

#include <iostream>
using namespace std;

class Complex {
private:
    int real, imag;
public:
    Complex(int r = 0, int i = 0) { real = r; imag = i; }

    Complex operator+(const Complex &other) {
        return Complex(real + other.real, imag + other.imag);
    }

    void show() { cout << real << " + " << imag << "i" << endl; }
};

int main() {
    Complex a(2, 3), b(4, 1);
    Complex c = a + b;
    c.show();
    return 0;
}
Output: 6 + 4i

6. Function Overriding (Recap)

Definition: Function overriding occurs when a derived class defines a function with the same signature as a function in its base class. With virtual functions, the derived version is selected at runtime based on the actual object type.

Overloading vs Overriding

FeatureOverloadingOverriding
ScopeSame classBase and derived class
SignatureMust differMust be identical
BindingCompile timeRuntime (if virtual)
Keyword requiredNovirtual and override recommended

Real-Life Example

All animals "speak", but a Dog barks and a Cat meows. The base behavior is replaced in each derived version.

Code Example

#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() { cout << "Some sound" << endl; }
};

class Dog : public Animal {
public:
    void sound() override { cout << "Bark" << endl; }
};

class Cat : public Animal {
public:
    void sound() override { cout << "Meow" << endl; }
};

int main() {
    Dog d;
    Cat c;
    d.sound();
    c.sound();
    return 0;
}
Output: Bark Meow

7. Virtual Functions

Definition: A virtual function is a member function declared in a base class using the virtual keyword and overridden in derived classes. When called through a base class pointer or reference, the function selected is the one in the actual object type, not the pointer type.

Key Points

  • Declared with the keyword virtual in the base class.
  • Once virtual, the function remains virtual in all derived classes.
  • Called through a pointer or reference to the base class.
  • Enables runtime polymorphism.
  • Implemented using the virtual table (vtable) mechanism.

Real-Life Example

A vehicle control system sends the "start" command. On a car, this starts the petrol engine; on an electric scooter, it powers the motor. The command is the same; the behavior depends on the concrete vehicle.

Syntax

class Base {
public:
    virtual returnType functionName(parameters);
};

class Derived : public Base {
public:
    returnType functionName(parameters) override;
};

Code Example

#include <iostream>
using namespace std;

class Vehicle {
public:
    virtual void start() { cout << "Vehicle starting" << endl; }
};

class Car : public Vehicle {
public:
    void start() override { cout << "Car engine started" << endl; }
};

class Scooter : public Vehicle {
public:
    void start() override { cout << "Scooter motor powered" << endl; }
};

int main() {
    Vehicle *v1 = new Car();
    Vehicle *v2 = new Scooter();
    v1->start();
    v2->start();
    delete v1;
    delete v2;
    return 0;
}
Output: Car engine started Scooter motor powered

8. Pure Virtual Functions

Definition: A pure virtual function is a virtual function declared in a base class but not defined there. It is written with = 0. A class containing at least one pure virtual function becomes an abstract class and cannot be instantiated directly.

Key Points

  • Declared with = 0.
  • The base class becomes an abstract class.
  • Derived classes must implement the pure virtual function to be concrete.
  • Used to define a common interface for derived classes.

Real-Life Example

An "Appliance" class has a pure virtual "operate" function. No one can create a generic "appliance"; one must create a WashingMachine or Refrigerator that implements operate().

Syntax

class AbstractClass {
public:
    virtual returnType functionName(parameters) = 0;    // pure virtual
};

Code Example

#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() = 0;               // pure virtual
};

class Circle : public Shape {
public:
    void draw() override { cout << "Drawing circle" << endl; }
};

class Square : public Shape {
public:
    void draw() override { cout << "Drawing square" << endl; }
};

int main() {
    // Shape s;        // ERROR: abstract class
    Shape *a = new Circle();
    Shape *b = new Square();
    a->draw();
    b->draw();
    delete a;
    delete b;
    return 0;
}
Output: Drawing circle Drawing square

Abstract Class Hierarchy

+-------------------+ | Shape | abstract (contains = 0) | draw() = 0 | +---------+---------+ / \ v v +---------+ +---------+ | Circle | | Square | | draw() | | draw() | +---------+ +---------+

9. Dynamic Binding

Definition: Dynamic binding, also known as late binding, is the process of linking a function call to its implementation at runtime. It occurs when a virtual function is invoked through a base class pointer or reference.

Conditions for Dynamic Binding

  • The function must be declared virtual in the base class.
  • The call must be made through a pointer or reference to the base class.
  • The actual object must be of a derived class.

Real-Life Example

A phone's "call" button reaches the dialer. Depending on whether the user is on a mobile phone, a landline, or a VoIP app, the actual call mechanism is determined at the time of the press.

Code Example

#include <iostream>
using namespace std;

class Payment {
public:
    virtual void pay() { cout << "Generic payment" << endl; }
};

class CreditCard : public Payment {
public:
    void pay() override { cout << "Paid by credit card" << endl; }
};

class Cash : public Payment {
public:
    void pay() override { cout << "Paid by cash" << endl; }
};

void checkout(Payment *p) {
    p->pay();      // resolved at runtime
}

int main() {
    CreditCard c;
    Cash k;
    checkout(&c);
    checkout(&k);
    return 0;
}
Output: Paid by credit card Paid by cash

10. Static and Dynamic Binding

Static Binding: Also called early binding, it links a function call to its definition at compile time.

Dynamic Binding: Also called late binding, it links a function call to its definition at runtime.

Comparison

Also calledEarly bindingLate binding
MechanismFunction name and signature matchVirtual table lookup
SpeedFasterSlightly slower
Used withOverloading, normal functions, non-virtual membersVirtual functions and overriding

11. Virtual Destructors

Definition: A virtual destructor is a destructor declared with the virtual keyword in the base class. It ensures that when a derived object is deleted through a base class pointer, the destructor of the derived class is also called, preventing resource leaks.

Why It Matters

  • Without a virtual destructor, deleting a derived object via a base pointer only invokes the base destructor.
  • This causes resource leaks in the derived class (memory, files, sockets).
  • Any class intended to be used polymorphically should have a virtual destructor.

Real-Life Example

When a building is demolished via the city's "demolish building" interface, the subcontractors hired by that building must also be released. A virtual destructor ensures all related resources are freed correctly.

Syntax

class Base {
public:
    virtual ~Base() { }
};

Code Example

#include <iostream>
using namespace std;

class Base {
public:
    Base() { cout << "Base created" << endl; }
    virtual ~Base() { cout << "Base destroyed" << endl; }
};

class Derived : public Base {
private:
    int *data;
public:
    Derived() {
        data = new int[100];
        cout << "Derived created" << endl;
    }
    ~Derived() {
        delete[] data;
        cout << "Derived destroyed" << endl;
    }
};

int main() {
    Base *p = new Derived();
    delete p;                     // both destructors run
    return 0;
}
Output: Base created Derived created Derived destroyed Base destroyed
Important: If the base destructor were not virtual, only Base destroyed would be printed, and the array allocated in Derived would leak.

12. Early and Late Binding

Early binding and static binding refer to the same concept; late binding and dynamic binding refer to the same concept. Both pairs describe when the function call is matched to the actual function definition.

Part B: Practical Topics

Practical 1: Implementing Compile-Time and Runtime Polymorphism

#include <iostream>
using namespace std;

// Compile-time: function overloading
class Calculator {
public:
    int multiply(int a, int b) { return a * b; }
    double multiply(double a, double b) { return a * b; }
};

// Runtime: virtual functions
class Animal {
public:
    virtual void speak() { cout << "Animal sound" << endl; }
};

class Dog : public Animal {
public:
    void speak() override { cout << "Woof" << endl; }
};

class Cat : public Animal {
public:
    void speak() override { cout << "Meow" << endl; }
};

int main() {
    Calculator c;
    cout << "Int multiply: " << c.multiply(4, 5) << endl;
    cout << "Double multiply: " << c.multiply(2.5, 4.0) << endl;

    Animal *a1 = new Dog();
    Animal *a2 = new Cat();
    a1->speak();
    a2->speak();
    delete a1;
    delete a2;

    return 0;
}
Output: Int multiply: 20 Double multiply: 10 Woof Meow

Practical 2: Implementing Function and Operator Overloading

#include <iostream>
using namespace std;

class Vector2D {
private:
    int x, y;
public:
    Vector2D(int a = 0, int b = 0) { x = a; y = b; }

    // Operator overloading
    Vector2D operator+(const Vector2D &other) {
        return Vector2D(x + other.x, y + other.y);
    }

    // Function overloading
    void scale(int factor) { x *= factor; y *= factor; }
    void scale(double factor) {
        x = (int)(x * factor);
        y = (int)(y * factor);
    }

    void show() { cout << "(" << x << ", " << y << ")" << endl; }
};

int main() {
    Vector2D v1(2, 3), v2(4, 1);
    Vector2D v3 = v1 + v2;            // operator overloading
    v3.show();

    v3.scale(2);                      // int overload
    v3.show();

    v3.scale(1.5);                    // double overload
    v3.show();

    return 0;
}
Output: (6, 4) (12, 8) (18, 12)

Practical 6: Working with Base-Class Pointers

#include <iostream>
using namespace std;

class Shape {
public:
    virtual double area() { return 0; }
};

class Rectangle : public Shape {
private:
    double l, w;
public:
    Rectangle(double length, double width) { l = length; w = width; }
    double area() override { return l * w; }
};

class Triangle : public Shape {
private:
    double base, height;
public:
    Triangle(double b, double h) { base = b; height = h; }
    double area() override { return 0.5 * base * height; }
};

int main() {
    Shape *shapes[2];

    shapes[0] = new Rectangle(4, 5);
    shapes[1] = new Triangle(6, 3);

    for (int i = 0; i < 2; i++) {
        cout << "Area: " << shapes[i]->area() << endl;
    }

    for (int i = 0; i < 2; i++) delete shapes[i];

    return 0;
}
Output: Area: 20 Area: 9

Practical 7: Demonstrating Dynamic Binding

#include <iostream>
using namespace std;

class Notification {
public:
    virtual void send() { cout << "Sending generic notification" << endl; }
};

class Email : public Notification {
public:
    void send() override { cout << "Sending email" << endl; }
};

class SMS : public Notification {
public:
    void send() override { cout << "Sending SMS" << endl; }
};

void notifyUser(Notification *n) {
    n->send();          // resolved at runtime
}

int main() {
    Email e;
    SMS s;

    notifyUser(&e);
    notifyUser(&s);

    return 0;
}
Output: Sending email Sending SMS

Practical 8: Implementing Virtual Destructors

#include <iostream>
using namespace std;

class Base {
public:
    Base() { cout << "Base constructor" << endl; }
    virtual ~Base() { cout << "Base destructor" << endl; }
};

class Derived : public Base {
private:
    int *buffer;
public:
    Derived() {
        buffer = new int[100];
        cout << "Derived constructor" << endl;
    }
    ~Derived() {
        delete[] buffer;
        cout << "Derived destructor" << endl;
    }
};

int main() {
    Base *b = new Derived();
    delete b;
    return 0;
}
Output: Base constructor Derived constructor Derived destructor Base destructor

What Would Happen Without virtual

Output (without virtual destructor): Base constructor Derived constructor Base destructor
Result: The Derived destructor would never run, and the buffer would leak.
