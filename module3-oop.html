Part A: Theory Topics

1. Function Overloading

Definition: Function overloading is the ability to define multiple functions with the same name but different parameter lists within the same scope. The compiler selects the correct function based on the number, types, or order of arguments passed.

Rules

  • Functions must have the same name.
  • They must differ in the number or types of parameters.
  • Return type alone cannot distinguish overloaded functions.

Syntax

returnType functionName(dataType param1);
returnType functionName(dataType param1, dataType param2);
returnType functionName(double param1);

Real-Life Example

A coffee shop accepts orders in different ways: a plain coffee, a coffee with sugar, or a coffee with sugar and milk. The word "order" is the same, but the number of choices differs, just like overloaded functions.

Code Example

#include <iostream>
using namespace std;

class Calculator {
public:
    int add(int a, int b) {
        return a + b;
    }
    double add(double a, double b) {
        return a + b;
    }
    int add(int a, int b, int c) {
        return a + b + c;
    }
};

int main() {
    Calculator calc;
    cout << calc.add(3, 4) << endl;
    cout << calc.add(2.5, 4.5) << endl;
    cout << calc.add(1, 2, 3) << endl;
    return 0;
}
Output: 7 7 6

2. Operator Overloading

Definition: Operator overloading allows operators (such as +, -, *, ==, <<) to be redefined so they work with user-defined types (classes). It lets objects be used with operators in a way that feels natural, similar to built-in data types.

Rules

  • Only existing C++ operators can be overloaded; new operators cannot be invented.
  • Overloading is done using a special function named operator followed by the operator symbol.
  • At least one operand must be a user-defined type.
  • Certain operators (:: , . , .* , ?:) cannot be overloaded.

Types of Operator Overloading

TypeDescriptionExample Operators
UnaryOperators acting on a single operand++, --, -, !
BinaryOperators acting on two operands+, -, *, /, ==, <

Two Implementation Methods

MethodDescription
Member functionOperator function is defined inside the class; the left operand is the calling object.
Friend functionOperator function is defined outside the class with friend access; both operands are passed as arguments.

Real-Life Example

The "+" symbol adds numbers in arithmetic, concatenates strings in text processing, and could be used to merge two shopping carts in a program. The same symbol performs different actions depending on the data types involved.

Syntax

// Member function form
returnType operator symbol (parameters) { }

// Friend function form
friend returnType operator symbol (parameters);

3. Friend Functions

Definition: A friend function is a non-member function that is granted access to the private and protected members of a class. It is declared inside the class using the keyword friend but is defined outside the class.

Key Points

  • It is not a member of the class.
  • It does not have a this pointer.
  • It is called like a normal function, without an object.
  • Friendship is granted, not taken.
  • Friendship is not inherited and is not mutual unless declared on both sides.

Real-Life Example

A bank's vault can only be accessed by its own staff (members). However, an authorized external auditor (friend function) may be granted special permission to inspect the vault.

Syntax

class ClassName {
private:
    int data;
public:
    friend returnType friendFunction(ClassName &obj);
};

returnType friendFunction(ClassName &obj) {
    // can access obj.data
}

Code Example

#include <iostream>
using namespace std;

class Box {
private:
    int width;
public:
    Box(int w) { width = w; }
    friend void printWidth(Box b);   // friend declaration
};

void printWidth(Box b) {
    cout << "Width: " << b.width << endl;  // accessing private member
}

int main() {
    Box b(15);
    printWidth(b);
    return 0;
}
Output: Width: 15

4. Friend Classes

Definition: A friend class is a class whose member functions are granted access to the private and protected members of another class. Friendship between classes is declared using the friend class statement.

Key Points

  • All member functions of the friend class can access private members of the granting class.
  • Friendship is one-way unless declared in both classes.
  • Friendship is not inherited.

Real-Life Example

A hospital's medical record system is private. However, the billing department (friend class) is authorized to access patient records for generating bills.

Syntax

class ClassA {
    friend class ClassB;    // ClassB can access ClassA's private members
private:
    int secret;
};

Code Example

#include <iostream>
using namespace std;

class Engine {
private:
    int horsepower = 500;
    friend class Mechanic;    // friend class declaration
};

class Mechanic {
public:
    void inspect(Engine e) {
        cout << "Horsepower: " << e.horsepower << endl;
    }
};

int main() {
    Engine e;
    Mechanic m;
    m.inspect(e);
    return 0;
}
Output: Horsepower: 500

5. Dynamic Memory Allocation

Definition: Dynamic memory allocation is the process of allocating memory at runtime (while the program is running) rather than at compile time. In C++, this is done using the new operator, and the memory is released using the delete operator.

Why It Is Needed

  • The required size of memory may not be known at compile time.
  • Large data structures may exceed the stack size.
  • Objects must outlive the scope in which they were created.

Real-Life Example

A hotel does not build rooms for every possible guest in advance. Instead, rooms are assigned (allocated) when a guest arrives and freed (deallocated) when the guest checks out. This is dynamic allocation.

Memory Regions Diagram

+---------------------------+ | STACK | <-- local variables, automatic +---------------------------+ | HEAP | <-- new / delete use this region +---------------------------+ | GLOBAL / DATA | <-- global and static variables +---------------------------+ | CODE | <-- program instructions +---------------------------+

6. New and Delete Operators

Definition: The new operator allocates memory dynamically on the heap and returns a pointer to it. The delete operator releases memory previously allocated by new to prevent memory leaks.

Syntax

// Allocating a single variable
dataType *ptr = new dataType;
dataType *ptr = new dataType(value);

// Allocating an array
dataType *arr = new dataType[size];

// Releasing memory
delete ptr;
delete[] arr;

Key Points

  • Use delete for single objects and delete[] for arrays.
  • Forgetting to call delete causes memory leaks.
  • Deleting the same pointer twice causes undefined behavior.
  • Use nullptr after deletion to avoid dangling pointers.

Real-Life Example

Booking a taxi is like using new (the car is assigned when needed). Ending the trip and releasing the car is like using delete (the resource becomes free).

Code Example

#include <iostream>
using namespace std;

int main() {
    int *p = new int(42);          // allocate single integer
    cout << "Value: " << *p << endl;
    delete p;                      // release memory

    int *arr = new int[5];         // allocate array
    for (int i = 0; i < 5; i++) arr[i] = i * 10;
    for (int i = 0; i < 5; i++) cout << arr[i] << " ";
    cout << endl;

    delete[] arr;                  // release array
    return 0;
}
Output: Value: 42 0 10 20 30 40

7. Identification of Classes and Objects

Definition: Identifying classes and objects is the process of analyzing a problem domain to discover the entities that should be modeled as classes and the instances that will exist as objects in the running system.

Steps for Identification

  1. Read the problem statement and list all nouns; these are candidate classes or objects.
  2. List all verbs; these often map to methods.
  3. Identify attributes of each candidate class.
  4. Identify relationships between candidate classes.
  5. Remove duplicates and irrelevant entities.

8. Relationships Between Classes

Definition: Relationships between classes describe how objects of one class are connected to objects of another class. They help model the structure of a system by defining how data and behavior flow between classes.

Types of Relationships

RelationshipStrengthDescription
AssociationWeakObjects are connected but independent
AggregationMediumWhole-part relationship; parts can exist independently
CompositionStrongWhole-part relationship; parts cannot exist independently

Relationship Strength Diagram

Weak Strong | | v v Association ------> Aggregation ------> Composition (uses) (has-a) (owns-a)

9. Association

Definition: Association is a relationship between two classes where objects of one class are connected to objects of another class, but neither owns the other. Both objects have independent lifecycles.

Types of Association

TypeDescriptionExample
One-to-OneOne object related to one other objectPerson and Passport
One-to-ManyOne object related to many objectsTeacher and Students
Many-to-ManyMany objects related to many othersStudents and Courses

Real-Life Example

A Teacher teaches many Students, and a Student is taught by many Teachers. Neither owns the other, and either can exist without the other.

Association Diagram

+----------+ +----------+ | Teacher |<------->| Student | +----------+ +----------+ teaches many is taught by many

Code Example

#include <iostream>
using namespace std;

class Student {
public:
    string name;
    Student(string n) { name = n; }
};

class Teacher {
public:
    string name;
    Teacher(string n) { name = n; }

    void teach(Student s) {
        cout << name << " teaches " << s.name << endl;
    }
};

int main() {
    Student s("Ali");
    Teacher t("Mr. Khan");
    t.teach(s);
    return 0;
}
Output: Mr. Khan teaches Ali

10. Aggregation

Definition: Aggregation is a special form of association that represents a whole-part relationship, where the part can exist independently of the whole. The whole does not control the lifecycle of the part.

Key Points

  • Represents a "has-a" relationship.
  • The part can exist even if the whole is destroyed.
  • Implemented in C++ by holding a pointer or reference to the part.

Real-Life Example

A Department has Professors. If the Department is closed, the Professors still exist and can join another department.

Aggregation Diagram

+-------------+ +------------+ | Department |<>------| Professor | +-------------+ +------------+ whole part (independent lifecycle of part)

Code Example

#include <iostream>
using namespace std;

class Professor {
public:
    string name;
    Professor(string n) { name = n; }
};

class Department {
private:
    Professor *prof;          // pointer, not owned
public:
    Department(Professor *p) { prof = p; }

    void show() {
        cout << "Department head: " << prof->name << endl;
    }
};

int main() {
    Professor p("Dr. Ahmed");
    Department d(&p);          // part exists independently
    d.show();
    return 0;
}
Output: Department head: Dr. Ahmed

11. Composition

Definition: Composition is a strong form of aggregation where the part cannot exist independently of the whole. If the whole is destroyed, its parts are also destroyed.

Key Points

  • Represents a strong "owns-a" relationship.
  • The part's lifecycle is controlled by the whole.
  • Implemented in C++ by holding the part as a value member or by allocating it inside the whole's constructor and deleting it in the destructor.

Real-Life Example

A Human has a Heart. If the Human dies, the Heart also ceases to function as part of that human.

Composition Diagram

+-----------+ +--------+ | Human |<*>------| Heart | +-----------+ +--------+ whole part (part dies with whole)

Code Example

#include <iostream>
using namespace std;

class Heart {
public:
    Heart() { cout << "Heart created" << endl; }
    ~Heart() { cout << "Heart destroyed" << endl; }
};

class Human {
private:
    Heart heart;              // value member, owned
public:
    Human() { cout << "Human created" << endl; }
    ~Human() { cout << "Human destroyed" << endl; }
};

int main() {
    Human h;
    return 0;
}
Output: Heart created Human created Human destroyed Heart destroyed

Practical 1: Implementing Function Overloading

#include <iostream>
using namespace std;

class Shape {
public:
    double area(double side) {
        return side * side;                    // square
    }
    double area(double length, double width) {
        return length * width;                 // rectangle
    }
    double area(float radius) {
        return 3.14159 * radius * radius;      // circle
    }
};

int main() {
    Shape s;
    cout << "Square area: " << s.area(5.0) << endl;
    cout << "Rectangle area: " << s.area(4.0, 6.0) << endl;
    cout << "Circle area: " << s.area(3.0f) << endl;
    return 0;
}
Output: Square area: 25 Rectangle area: 24 Circle area: 28.2743

Practical 2: Implementing Unary and Binary Operator Overloading

Unary Operator Overloading (++)

#include <iostream>
using namespace std;

class Counter {
private:
    int value;
public:
    Counter(int v) { value = v; }

    Counter operator++() {          // prefix ++
        ++value;
        return *this;
    }

    Counter operator++(int) {       // postfix ++
        Counter temp = *this;
        value++;
        return temp;
    }

    void show() { cout << "Value: " << value << endl; }
};

int main() {
    Counter c(5);
    ++c;
    c.show();        // Value: 6
    c++;
    c.show();        // Value: 7
    return 0;
}
Output: Value: 6 Value: 7

Binary Operator Overloading (+)

#include <iostream>
using namespace std;

class Complex {
private:
    int real, imag;
public:
    Complex(int r = 0, int i = 0) { real = r; imag = i; }

    Complex operator+(const Complex &other) {
        return Complex(real + other.real, imag + other.imag);
    }

    void show() { cout << real << " + " << imag << "i" << endl; }
};

int main() {
    Complex c1(3, 4), c2(1, 2);
    Complex c3 = c1 + c2;
    c3.show();
    return 0;
}
Output: 4 + 6i

Practical 3: Operator Overloading Using Member Functions

#include <iostream>
using namespace std;

class Distance {
private:
    int meters;
public:
    Distance(int m = 0) { meters = m; }

    Distance operator+(const Distance &d) {   // member function
        return Distance(meters + d.meters);
    }

    bool operator<(const Distance &d) {
        return meters < d.meters;
    }

    void show() { cout << meters << " m" << endl; }
};

int main() {
    Distance a(100), b(250);
    Distance c = a + b;
    c.show();
    cout << (a < b ? "a is shorter" : "b is shorter") << endl;
    return 0;
}
Output: 350 m a is shorter

Practical 4: Operator Overloading Using Friend Functions

#include <iostream>
using namespace std;

class Complex {
private:
    int real, imag;
public:
    Complex(int r = 0, int i = 0) { real = r; imag = i; }

    friend Complex operator+(const Complex &a, const Complex &b);
    friend ostream& operator<<(ostream &out, const Complex &c);
};

Complex operator+(const Complex &a, const Complex &b) {
    return Complex(a.real + b.real, a.imag + b.imag);
}

ostream& operator<<(ostream &out, const Complex &c) {
    out << c.real << " + " << c.imag << "i";
    return out;
}

int main() {
    Complex c1(2, 3), c2(4, 1);
    Complex c3 = c1 + c2;
    cout << c3 << endl;
    return 0;
}
Output: 6 + 4i

Practical 8: Implementing Aggregation and Composition

Aggregation Example

#include <iostream>
using namespace std;

class Player {
public:
    string name;
    Player(string n) { name = n; }
};

class Team {
private:
    Player *members[5];       // pointers, not owned
    int count;
public:
    Team() { count = 0; }

    void addPlayer(Player *p) {
        if (count < 5) members[count++] = p;
    }

    void show() {
        cout << "Team members:" << endl;
        for (int i = 0; i < count; i++)
            cout << "- " << members[i]->name << endl;
    }
};

int main() {
    Player p1("Ali"), p2("Sara"), p3("John");
    Team team;
    team.addPlayer(&p1);
    team.addPlayer(&p2);
    team.addPlayer(&p3);
    team.show();
    return 0;
}
Output: Team members: - Ali - Sara - John

#include <iostream>

Practical 9: Designing Real-World Object Relationships

Example: University System

#include <iostream>
#include <vector>
using namespace std;

// --- Part classes ---
class Course {
public:
    string title;
    Course(string t) { title = t; }
};

class Professor {
public:
    string name;
    Professor(string n) { name = n; }
};

// --- Aggregation: Department has Professors (independent) ---
// --- Composition: Department owns Courses ---
class Department {
private:
    string name;
    Professor *head;              // aggregation
    vector<Course> courses;       // composition
public:
    Department(string n, Professor *h) {
        name = n;
        head = h;
    }
    void addCourse(string t) {
        courses.push_back(Course(t));
    }
    void show() {
        cout << "Department: " << name << endl;
        cout << "Head: " << head->name << endl;
        cout << "Courses:" << endl;
        for (auto &c : courses)
            cout << " - " << c.title << endl;
    }
};

int main() {
    Professor p("Dr. Khan");
    Department d("Computer Science", &p);
    d.addCourse("OOP");
    d.addCourse("Data Structures");
    d.addCourse("Databases");
    d.show();
    return 0;
}
Output: Department: Computer Science Head: Dr. Khan Courses: - OOP - Data Structures - Databases
